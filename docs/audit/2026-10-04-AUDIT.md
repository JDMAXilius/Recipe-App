# Otto — full audit, 2026-10-04

**Scope:** the whole repo at `8d7789a0` → `main`: Supabase backend (25 migrations, 7 edge
functions, live advisors), payments and entitlements (RevenueCat), authentication, the AI consent
path, client config, and release readiness. **Method:** every claim below was checked against the
code, the installed SDK's own documentation (`node_modules/react-native-purchases/dist/purchases.d.ts`,
`@supabase/auth-js` GoTrueClient), Supabase's live security/performance advisors on the production
project, Apple's App Review Guidelines (fetched 2026-10-04), and Anthropic's Commercial Terms
(fetched 2026-10-04). Supabase's and RevenueCat's doc sites are egress-blocked from the cloud
container, so for those the installed SDK source is the citation. Nothing here is assumed.

**Verification after the fixes:** `tsc` 0 errors · eslint clean · `npm test` 329/329 (3 new).
Edge functions can't be type-checked here (no Deno) — `deno check` is step 0 of the deploy ticket.

## Verified correct (so you know what was covered)

**Backend.** RLS is enabled on every table; all own-row policies use `(select auth.uid())`; the household read policies go through `private.is_household_member/shares_household` (SECURITY DEFINER with fixed search_path, moved out of the API schema in `20260723120000`). The two anon-callable SECURITY DEFINER functions the advisor flags (`get_recipe_share`, `get_list_share`) are the capability-URL share readers, documented as intentional in `20260924214553`; `join_household` validates the code. `admin_delete_user_data` is `security definer set search_path to ''` and granted to `service_role` only; kitchens, members and memberships cascade from `auth.users`. `verify_jwt` is on for every function except the webhook (by design; shared-secret auth). `import-recipe`'s SSRF guard resolves every hop, blocks v4/v6 private, link-local, NAT64 and mapped forms, caps bytes, and documents the residual DNS-rebinding race honestly. `generate-recipe`/`resolve-nutrition` send **only** the user's text/photo and diet/cuisine preference to Anthropic — no email, uid or device id — and log token counts only. Output is JSON-schema constrained; prompt injection in a pasted page can at worst produce a wrong recipe, not a different action. No secret is tracked in git (`.env.development` holds the publishable anon key only, by recorded decision; `credentials/` and `.env*` are ignored). Storage: insert only into your own folder, no listing policy on the public bucket, deletes are service-role only.

**Payments.** `Purchases.configure` runs once at module scope before any use; `logIn(uid)` on auth; membership is derived only from `customerInfo.entitlements.active.club`; `syncPurchasesForResult` runs once per account per device (the SDK warns repeated syncs can move a subscription between accounts sharing an Apple ID); purchase results distinguish ok / unconfirmed / pending / cancelled / error and never say "welcome" without the entitlement; restore has the same sync fallback. The webhook ignores the event body's state and re-reads the subscriber from RevenueCat's API (order-independent, idempotent). Paywall shows price, period, trial, Restore, Terms and Privacy (and now the name + renewal line).

**Auth.** Sign in with Apple: raw nonce → SHA-256 to Apple, raw to `signInWithIdToken` (correct). Native Google uses the SDK's idToken with `signInWithIdToken`; the provider's "Skip nonce check" is the documented requirement for the Google iOS SDK, which can't carry a nonce — the trade-off is accepted and recorded in `oauth.native.ts`. Facebook runs in an ephemeral browser session; `sessionFromUrl` handles both `?code=` and `#tokens`. `onAuthStateChange` never awaits inside the callback. `user_metadata` (`username`, `onboarded_at`) is client-writable and is used **only** for display/onboarding, never for authorization. Account deletion revokes Sign in with Apple tokens with an ES256 client secret (`iss` team, `sub` client id, `aud` appleid.apple.com, 5-min exp) — matches Apple's token-revocation API. `changePassword` proves the current password by re-signing in.

**AI consent (5.1.2(i)).** Every path that reaches Anthropic is gated: Ask Otto Send and chips (`ChatScreen.tsx:123,158`), link/text/photo imports (`AddSheet.tsx:81,104,123`, before the camera opens), nutrition matching silently (`nutrition.queries.ts:64`). No other consumer of `sendChatStreaming`/`invokeEdge` exists (grep). The sheet names Anthropic, lists the data, links the Privacy Policy, and the "doesn't train on what you send" line is backed by Anthropic's Commercial Terms, Section B: *"Anthropic may not train models on Customer Content from Services."* Apple's text, verbatim: *"You must clearly disclose where personal data will be shared with third parties, including with third-party AI, and obtain explicit permission before doing so."*

**Privacy manifest and permissions.** `NSPrivacyTracking: false`, no tracking domains, no analytics/ad SDK in `package.json`; the seven declared data types match the App Privacy label; permission strings are specific and honest.

**Client hygiene.** Every listener found (RevenueCat customer-info, auth state, speech, AppState) is removed or intentionally app-lifetime; kv keys are typed and zod-validated; `getSession()` is used for UI only (the server verifies tokens).
